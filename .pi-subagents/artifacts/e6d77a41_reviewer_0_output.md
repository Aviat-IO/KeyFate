## Review

- **High — stale disclosure workers can reacquire recipient ownership and duplicate disclosures.** `frontend/src/lib/cron/disclosure-helpers.ts:25-47` upserts a recipient lease using only `(secret_id, recipient_email)` and unconditionally replaces every non-`sent` row's `lease_id` with the caller-supplied lease. It never verifies that `params.leaseId` is still the current `secrets.processing_lease_id`. Failure path: worker A claims the secret and stalls before claiming the recipient; after 15 minutes worker B takes over and claims the recipient with lease B; worker A resumes and the upsert replaces lease B with stale lease A, after which both workers may call the provider. This contradicts the stale-worker fence required by `openspec/changes/harden-production-readiness/specs/infrastructure/spec.md:50-52` and the design invariant at `design.md:83`. The PostgreSQL test does not exercise this race: `frontend/scripts/postgres-concurrency.test.ts:88-97` manually creates a row owned by the takeover lease and only tests stale *completion*, while `:111-130` expressly permits arbitrary retry leases without validating parent ownership. Release should remain blocked until recipient claim is conditional on the current, live parent lease in the same PostgreSQL statement and the stale-claim/takeover interleaving is tested.

- **High — migration `0011` can fail on valid legacy production data.** `frontend/drizzle/0011_enforce_disclosure_recipient_idempotency.sql:1` directly adds `UNIQUE(secret_id, recipient_email)` without reconciling duplicates. The pre-`0011` schema has only non-unique indexes (`frontend/drizzle/0000_initial_schema_with_rate_limits.sql:510-511`), and the old workers inserted a new disclosure row on each attempt because `onConflictDoNothing()` had no applicable recipient uniqueness constraint (old `process-reminders.ts`, visible at HEAD lines 260-281). Therefore an existing database may legally contain duplicate recipient rows, and PostgreSQL will abort the Railway pre-deploy migration when building the constraint. `frontend/scripts/migration-compatibility.test.ts:57-60` seeds only one legacy row; its “duplicate rejected” assertion at `:102-111` inserts the duplicate *after* migration, so it does not validate the dangerous upgrade case. This makes the “existing-schema migration”/“compatible migrations” completion claim in `openspec/changes/harden-production-readiness/tasks.md:25-26` materially overstated. Before release, production must be queried for duplicates and the generated migration sequence must include a deterministic, outcome-preserving reconciliation path tested with pre-existing duplicate rows.

### Correct / residual external risks

- The parent secret claim itself is atomic (`frontend/src/lib/cron/disclosure-claim.ts:13-40`), export completion/failure writes are lease-fenced (`frontend/src/lib/cron/process-exports.ts:57-91,135-146`), rate-limit admission is a single PostgreSQL upsert and fails closed (`frontend/src/lib/rate-limit-db.ts:29-77`), and OTP validation serializes attempts with `FOR UPDATE` (`frontend/src/lib/auth/otp.ts:134-147`).
- Runtime migration separation is coherent: Railway pre-deploy invokes the runtime migrator (`frontend/railway.json:7-9`), the migrator fails nonzero (`frontend/scripts/migrate.ts:31-38`), and the image CMD starts only the built application (`frontend/Dockerfile:40-41`).
- No vulnerability scanner was run and no repository file was modified. No tests were rerun; this was a read-only source/diff/evidence review. `plan.md` was absent, and the available `progress.md` describes an unrelated Bitcoin demo PR, so neither supplied usable remediation evidence.
- Even after the two high findings are fixed, production remains NO-GO pending the already-recorded external gates: credentialed Railway migration/promotion evidence for the exact green SHA, branch protection/deployment approval, provider and scheduled-job staging E2E, live Nostr recovery, funded signet recovery, Railway backup/PITR restore with RPO/RTO, monitoring/rollback ownership, and retirement of the legacy ESLint baseline.
